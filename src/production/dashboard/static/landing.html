Rolling 3.0σ Gaussian Anomaly Detection

Asset prices follow non-stationary random walks; computing standard deviation on raw prices produces drifting statistical errors. CryptoPulse calculates Gaussian Z-scores on price returns $R_t = \frac{P_t - P_{t-1}}{P_{t-1}}$ over rolling 30-period sliding deques, filtering true volatility spikes with zero lookahead bias.

MATHEMATICAL FORMULATION
Z = (R_t - μ) / σ • |Z| ≥ 3.0σ
Strict Temporal Guarantee: Current return $R_t$ is scored strictly against historical buffer prior to window mutation.

Architectural Rationale for Examiners

Concrete architectural justifications for external viva voce examinations and technical defense.

Q1: WHY KAFKA + SPARK?

Decoupled Buffer & State

Direct WebSocket writes to ClickHouse cause packet drops during table compaction. Kafka acts as an immutable commit log; Spark manages stateful tumbling windows across distributed partitions.

Q2: WHY CLICKHOUSE OLAP?

SIMD Vectorized Execution

PostgreSQL row storage suffers buffer cache thrashing at high ingest. ClickHouse stores columns contiguously with ZSTD, evaluating aggregations over 100,000+ rows in under 5 milliseconds.

Q3: LATE-ARRIVING DATA?

Event-Time Watermarks

Spark maintains a 30-second watermark: withWatermark('timestamp', '30s'). Ticks delayed up to 30s update stateful windows; older ticks are discarded to bound memory growth.
