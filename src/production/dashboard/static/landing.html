04 // Architectural Rationale

Technical Defense & Examiner Reference

Key architectural trade-offs formulated for external portfolio examination and viva voce defense.

RATIONALE 01

Why Kafka + Spark?

Direct WebSocket writes to ClickHouse cause packet drops during table compaction. Kafka acts as an immutable commit log; Spark manages stateful tumbling windows across distributed partitions.

RATIONALE 02

Why ClickHouse OLAP?

PostgreSQL row storage suffers buffer cache thrashing at high ingest. ClickHouse stores columns contiguously with ZSTD compression, evaluating analytical queries over 100,000+ rows in < 5 ms.

RATIONALE 03

Late-Arriving Ticks?

Spark maintains an event-time watermark: withWatermark('timestamp', '30s'). Ticks delayed up to 30 seconds update stateful windows; older ticks are dropped to bound memory.
